# 3. URL scheme, Open With, Services

## Goal

Start or focus a session from anywhere else on the Mac: Finder, a script, an editor, a browser link, the Dock.
Patchbay becomes the place "open this folder with an agent" goes to.

## User flow

- **Dock / Open With:** drop a folder on the Patchbay icon, or Finder → right-click folder → Open With → Patchbay.
  The New Session sheet opens with the folder filled in.
- **URL:** `patchbay://new?dir=/path/to/project&agent=claude` opens the sheet prefilled.
  `patchbay://session/<uuid>` selects that session (useful in notes and scripts).
- **Services:** Finder → right-click folder → Services → **New Patchbay Session Here**; also in any app's
  Services menu for selected text that is a path.
- Scripts: `open "patchbay://new?dir=$PWD"` works from any shell, including shells outside Patchbay.

## Design

All of these end in one function, `store.open(directory:agent:)`, which shows the New Session sheet prefilled.

- **Info.plist** is generated by `build.sh`, so add there:
  - `CFBundleURLTypes` with scheme `patchbay`;
  - `CFBundleDocumentTypes` with `public.folder` and role `Viewer` (this is what makes Open With and Dock drops
    work);
  - `NSServices` with `NSMessage` = `openFolder`, `NSSendFileTypes` = `public.folder`.
- **Receiving:** `.onOpenURL { }` on the `Window` content handles URLs; the delegate's
  `application(_:open:)` handles Dock drops and Open With. The Services handler is a method on an object set as
  `NSApp.servicesProvider`.
- **Never auto-start.** Anything arriving from outside can come from a web page (`<a href="patchbay://…">`). The
  link may only prefill the sheet; the user presses Start. Ignore a `prompt=` parameter entirely, or put it
  in the prompt field unsent. Validate `dir` exists and is a directory; normalise `..`.
- After changing Services entries, macOS caches them; `/System/Library/CoreServices/pbs -update` refreshes the
  list while testing. Services only appear for apps in `/Applications` or `~/Applications`, so test from the
  installed copy, which matters because the test copy runs from `build/`.
- Pitfall: with `Window` (single-instance) `onOpenURL` reuses the window; with `WindowGroup` it would open a new
  one. Keep `Window`.

## Files

| File | Change |
|---|---|
| `build.sh` | URL type, document type, `NSServices` |
| `PatchbayApp.swift` | `onOpenURL`, `application(_:open:)`, services provider |
| `SessionStore.swift` | `open(directory:agent:)`, `NewSessionSheet` prefill |
| `NewSessionSheet.swift` | accept initial directory/agent |

## Testing

Test copy has a different bundle ID but the same URL scheme, so the two apps would compete for `patchbay://`.
Give the test copy's Info.plist a `patchbay-test` scheme in `start_test_app`, or test with `open -a` on the
installed app. Try: `open -a Patchbay ~/dev/patchbay`, `open "patchbay://new?dir=/tmp"`, a bad path, a path
with spaces and `%20`, and `dir=/etc/../tmp`.

- `NSApp.servicesProvider` and `@objc` methods called by the system.
